Camera Power Management

Low power / high battery drain logic — awx-pio weather station firmware

Primary source: src/ArduinoWeatherStation.ino (runtime once-per-minute block) • INA averaging: src/ina219.ino, src/ina219.h • helpers: src/wxUtilities.ino, src/wxTimeNet.ino

INA219 readings (inputs to camera logic)

Camera enable/shutoff uses the global values ina219a_solar_ma, ina219a_solar_volts, ina219b_battery_ma, and ina219b_battery_volts. These come from ina219Poll() and finalizeInaMinute() in src/ina219.ino (not the Renogy fields in the weather string).

  • Sample rate: ina219Poll() runs every INA_READ_INTERVAL_SEC seconds (default 1; override in platformio.ini with -D INA_READ_INTERVAL_SEC=2).
  • Per read: each INA219 conversion uses the chip’s 128-sample hardware average (setAmpAverage() / setVoltAverage() in setup()).
  • Per minute: samples are accumulated into running sums; globals are updated as the arithmetic mean of all samples so far in the current runtime minute.
  • End of runtime minute: when seconds > 59 in loop(), finalizeInaMinute() runs first, recomputes that mean, logs sample count and effective Hz, then clears sums for the next minute.
  • Battery current offset: every battery sample adds battery_ma_offset (+30 mA) before averaging.
Camera decisions use the completed runtime-minute average (values left by finalizeInaMinute() in the same seconds > 59 block). Uploaded weather lines on RTC minute rollovers call getWeatherString() without finalizing there, so fields 15–18 in a log row can reflect the in-progress minute mean until the next runtime finalize.

Overview

Camera power logic runs once per runtime minute (when seconds > 59), immediately after finalizeInaMinute(), using the INA219 minute-mean values above.

Three cameras are managed:

  • North (PG launch)
  • South (HG launch)
  • BrainBox
Turning cameras off also clears the keepUbiquitiOn flag, allowing continuous WiFi (required for camera operation) to be disabled and return to periodic upload mode.

On Turning Cameras On

Path A — God mode (telnet)

When camStatus.godMode is set (telnet), auto-enable runs from hour() >= camGodModeStartHour (default 10:00) until night goToSleep(). Requires not camStatus.badWeather. No solar or battDrainmA checks. Weather flag O in field 20 when active.

Path B — Normal daytime, good power

When god mode is off, cameras are automatically enabled only when all of the following are met (minute-mean INA values):

  1. Time window: after sunrise, and before sunset − 120 minutes (120 min buffer because mountains block sun early in the evening).
  2. Solar charging is strong enough:
    • ina219a_solar_ma > 500 and ina219a_solar_volts > 14, or
    • ina219a_solar_volts > 17.5
  3. No bad-weather hold: camStatus.badWeather == false (set manually via telnet command X).
  4. Drain budget OK: battDrainmA > camDrainmAAllowTurnOn (> −3000 mA·min, ~50 mAh net deficit since boot). Uses the integral before this minute’s battDrainmA += ina219b_battery_ma (see below).

Turn-on does not use instantaneous battery amps. Solar gates use minute-mean ina219a_*; the battery gate is cumulative battDrainmA only. Either solar branch can qualify alone (e.g. ina219a_solar_volts > 17.5 with low panel current).

What gets enabled

  • keepUbiquitiOn = true (persisted to EEPROM)
  • WiFi enabled
  • South camera enabled
  • North camera enabled only if humidityInside < 80% (North camera is unreliable in high humidity)
BrainBox camera is NOT auto-enabled. It is only controlled manually via telnet.

Off Turning Cameras Off — Battery Drain

In normal mode (not god mode), daytime shutoff requires sustained serious deficit, not every brief blip below zero. Values are the runtime minute mean from finalizeInaMinute() (includes +30 mA offset on battery current). A minute counts as serious drain only when ina219b_battery_ma < camDrainMaThreshold (< −120 mA).

Variable Type Meaning
battDrainMinutes int Consecutive minutes of serious discharge (< −120 mA)
battDrainmA float Running sum of ina219b_battery_ma each minute (mA·min; ÷ 60 ≈ mAh). Net since boot; charging minutes add back.

Each minute: serious discharge (ina219b_battery_ma < −120)

  • Increment battDrainMinutes
  • If any of the following trip, all three cameras are disabled and keepUbiquitiOn is cleared:
# Condition Description
1 battDrainMinutes >= 15 15+ consecutive minutes of serious discharge (>120 mA net out)
2 battDrainmA < −18000 Cumulative net deficit exceeds ~300 mAh since boot
3 ina219b_battery_volts < camLowVoltageShutoff and battDrainMinutes >= 10 Low voltage with sustained drain — 13.15 V (LiFePO4) or 12.5 V (AGM). LiFePO4 voltage stays flat until nearly empty; this only fires when actually low.
4 ina219a_solar_ma < 250 and battDrainMinutes >= 12 Cloudy-day pattern: serious drain while solar cannot support loads

Each minute: battery is charging

Condition: ina219b_battery_ma > 50 or ina219a_solar_volts > 16

  • If battDrainMinutes > 0, reset it to 0
  • Decrement battDrainMinutes by 1 (allows recovery from near-threshold state)

Each minute: neutral (−120 to +50 mA, not clearly draining or charging)

  • Decrement battDrainMinutes by 1 if > 0 (slow decay instead of instant reset)

Order each runtime minute (seconds > 59)

  1. finalizeInaMinute() — freeze minute-mean ina219_* globals
  2. Evaluate shouldAutoEnableCams (uses battDrainmA as accumulated through previous minutes)
  3. Drain shutoff logic (god mode skips this block)
  4. battDrainmA += ina219b_battery_ma — add this minute’s mean battery mA (mA·min); resets only on reboot

Weather upload field 22 reports battDrainmA / 60 as mAh. Field 21 reports battDrainMinutes only when > 0.

Off Other Camera-Off Paths

Evening cutoff (6 PM hour)

During hour() == 18 (with a minute condition that effectively covers the entire hour), all cameras are disabled and keepUbiquitiOn is cleared. Intended as an end-of-day shutdown.

Night / critical battery → full sleep (goToSleep())

All cameras (plus WiFi and Ethernet) are disabled when:

  • Outside the sunrise/sunset awake window, or
  • Battery voltage drops below battery_critical_voltage: 11.8 V (AGM) or 13.0 V (LiFePO4)

This also runs at boot if it is nighttime.

Manual control (telnet)

  • B / S / N — toggle individual cameras
  • a — turn all cameras off
  • X — set/clear bad-weather flag (blocks auto turn-on)
  • God mode toggle — solar/battery gating bypassed for auto on (see telnet help in wxTimeNet.ino)

EEPROM Persistence

Camera desired on/off state is stored in EEPROM via the camStatus struct (SouthDesireOn, NorthDesireOn, BrainDesireOn, badWeather, godMode) so state survives reboots.

On boot, any camera marked "desired on" is re-powered. The keepUbiquitiOn flag is also restored from EEPROM.

Decision Flow (simplified)

Each runtime minute (seconds > 59) │ ├─ finalizeInaMinute() → minute-mean ina219a_* / ina219b_* │ ├─ God mode AND hour >= 10 AND not badWeather? │ YES → Enable South/North (+ WiFi keep-on) │ ├─ Else: daytime window + solar OK + not badWeather + battDrainmA > -3000? │ YES → Enable South/North (+ WiFi keep-on) │ ├─ (Not god mode) Serious discharge (minute-mean ina219b_battery_ma < -120)? │ YES → Increment battDrainMinutes │ ├─ 15+ serious-drain mins OR battDrainmA < -18000 │ │ OR (volts < camLowVoltage AND 10+ serious mins) │ │ OR (solar < 250mA AND 12+ serious mins)? │ │ YES → Disable ALL cameras + clear keepUbiquitiOn │ └─ NO → Keep tracking │ CHARGING (ma > 50 OR solar > 16V) → Reset/decrement drain counters │ NEUTRAL → Decrement battDrainMinutes (slow decay) │ ├─ battDrainmA += ina219b_battery_ma (minute mean) │ ├─ Hour == 18 (6 PM)? → Disable all cameras │ └─ Night OR critical battery voltage? → goToSleep() (all cameras off)

Design Intent

Auto-run cameras only when solar is charging well enough to support them, and cut them when clouds or load cause sustained serious battery drain — before the station hits critical voltage and enters full sleep mode. LiFePO4 voltage is a poor early indicator (flat until nearly empty), so current-based and solar-deficit metrics carry most of the daytime shutoff logic; voltage is only used after 10+ minutes of serious discharge.

Drain metrics (battDrainMinutes, battDrainmA / 60 as mAh) are also included in the weather upload string for remote monitoring. Telnet status can show ina219_avgReadHz and samples per minute for the last finalized INA minute.
