Camera Power Management

Low power / high battery drain logic — awx-pio weather station firmware

Primary source: src/ArduinoWeatherStation.ino (once-per-minute loop) • helpers in src/wxUtilities.ino, src/wxTimeNet.ino

Overview

Camera power logic runs once per minute in the main loop, using INA219 sensor readings for battery current/voltage (ina219b_*) and solar panel (ina219a_*).

Three cameras are managed:

  • North (PG launch)
  • South (HG launch)
  • BrainBox
Turning cameras off also clears the keepUbiquitiOn flag, allowing continuous WiFi (required for camera operation) to be disabled and return to periodic upload mode.

On Turning Cameras On — Daytime, Good Power

Cameras are automatically enabled only when all of the following conditions are met:

  1. Time window: after sunrise, and before sunset − 120 minutes (120 min buffer because mountains block sun early in the evening).
  2. Solar charging is strong enough:
    • ina219a_solar_ma > 500 and ina219a_solar_volts > 14, or
    • ina219a_solar_volts > 17.5
  3. No bad-weather hold: camStatus.badWeather == false (set manually via telnet command X).
  4. Drain budget OK: battDrainmA > −500 (cumulative net drain since boot has not exceeded threshold).

What gets enabled

  • keepUbiquitiOn = true (persisted to EEPROM)
  • WiFi enabled
  • South camera enabled
  • North camera enabled only if humidityInside < 80% (North camera is unreliable in high humidity)
BrainBox camera is NOT auto-enabled. It is only controlled manually via telnet.

Off Turning Cameras Off — Battery Drain

Two tracked metrics drive the drain-based shutdown:

Variable Type Meaning
battDrainMinutes int Count of consecutive minutes the battery is discharging
battDrainmA float Running sum of ina219b_battery_ma added each minute (mA·min; ÷ 60 ≈ mAh). Never reset except on reboot.

Each minute: battery is discharging (ina219b_battery_ma < 0)

  • Increment battDrainMinutes
  • If any of the following trip, all three cameras are disabled and keepUbiquitiOn is cleared:
# Condition Description
1 battDrainMinutes >= 5 5 or more consecutive minutes of battery drain
2 battDrainmA < −8000 Cumulative drain exceeds ~133 mAh net since boot
3 ina219b_battery_volts < 12.5 and battDrainMinutes > 1 Low voltage (< 12.5 V) with 2+ minutes of drain

Each minute: battery is charging

Condition: ina219b_battery_ma > 50 or ina219a_solar_volts > 16

  • If battDrainMinutes > 0, reset it to 0
  • Decrement battDrainMinutes by 1 (allows recovery from near-threshold state)

Each minute: neutral (not clearly draining or charging)

  • battDrainMinutes = 0

Regardless of state, each minute: battDrainmA += ina219b_battery_ma

Off Other Camera-Off Paths

Evening cutoff (6 PM hour)

During hour() == 18 (with a minute condition that effectively covers the entire hour), all cameras are disabled and keepUbiquitiOn is cleared. Intended as an end-of-day shutdown.

Night / critical battery → full sleep (goToSleep())

All cameras (plus WiFi and Ethernet) are disabled when:

  • Outside the sunrise/sunset awake window, or
  • Battery voltage drops below battery_critical_voltage: 11.8 V (AGM) or 13.0 V (LiFePO4)

This also runs at boot if it is nighttime.

Manual control (telnet)

  • B / S / N — toggle individual cameras
  • a — turn all cameras off
  • X — set/clear bad-weather flag (blocks auto turn-on)

EEPROM Persistence

Camera desired on/off state is stored in EEPROM via the camStatus struct (SouthDesireOn, NorthDesireOn, BrainDesireOn, badWeather) so state survives reboots.

On boot, any camera marked "desired on" is re-powered. The keepUbiquitiOn flag is also restored from EEPROM.

Decision Flow (simplified)

Every minute │ ├─ Daytime + good solar + not badWeather + battDrainmA > -500? │ YES → Enable South/North cameras + continuous WiFi │ ├─ Battery discharging (ina219b_battery_ma < 0)? │ YES → Increment battDrainMinutes │ ├─ 5+ drain mins OR battDrainmA < -8000 OR (volts < 12.5V AND drain > 1 min)? │ │ YES → Disable ALL cameras + clear keepUbiquitiOn │ └─ NO → Keep tracking │ CHARGING (ma > 50 OR solar > 16V) → Reset/decrement drain counters │ NEUTRAL → battDrainMinutes = 0 │ ├─ Hour == 18 (6 PM)? → Disable all cameras │ └─ Night OR critical battery voltage? → goToSleep() (all cameras off)

Design Intent

Auto-run cameras only when solar is charging well enough to support them, and cut them quickly when clouds or load cause sustained battery drain — before the station hits critical voltage and enters full sleep mode.

Drain metrics (battDrainMinutes, battDrainmA / 60 as mAh) are also included in the weather upload string for remote monitoring.
